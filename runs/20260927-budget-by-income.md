日期：2026-09-27

## Phase A 事实表

- **项目**：开源「个人财产管理」Skill，跑在豆包，公益、可自改、无个人信息、中文版、配 README。
- **目标（一句话）**：帮中国大陆零基础用户上传支付宝/微信账单后按月对账、分析开销、给下月预算，逐步存钱并规划储蓄与保险，实现量入为出。
- **验收**：① 每月能传账单→开销分析+下月预算+储蓄/保险预算；② 摸底能引导用户弄出自己的数字；③ 自检对比"当前花法 vs 按 Skill 花法"一年后后果。
- **红线**：不荐具体产品；不给法律/税务意见；保险只给预算+配置比例+优先级并提醒找持牌；不收集个人身份信息，只问金额。
- **目标用户**：中国大陆零基础人群（刚毕业/月光/被家庭压力逼省钱），会用豆包；已储蓄但不会分配者（路线 B）。
- **载体**：豆包 Skill + README；小红书 marketing 由作者负责。
- **功能（全做）**：记账/对账、开销分析、下月预算、阶梯储蓄、储蓄+保险预算、存量资金配置、自检对比。
- **最薄弱环节**：账单解析可靠性（对话澄清兜底）、零基础不会导账单（内置教学）。

**[未知] 处理情况**：
1. 微信/支付宝账单格式 → **已查证**（微信 xlsx 11 列；支付宝 csv GB18030 12 列；收/支列为权威）。
2. "兴趣分析"模块 → 收敛为"开销分析"（按类汇总消费），不再单列。
3. 保险配置优先级 → **已查证**（标准普尔象限；保费≈年收入 5–15%；双十定律）。
4. 储蓄率档位 → **已定**：阶梯 5→10→15→20%，3 个月一阶。
5. 保险/储蓄计算口径 → **已定**：增量（占收入）与存量（标准普尔占资产）分开。

## Phase B 全量决策树地图

- **路径 A · 账单驱动**（主干）：摸底 → 教导出账单 → 解析 → 开销分析 → 储蓄状态识别 → 预算+配置 → 自检 → 月度复检。
- **路径 B · 手动登记**：纯手写记账（被剪，作为"手抄降级"保留）。
- **路径 C · 问卷摸底驱动**：仅用于首用摸底，不替代账单。
- **路径 D · 不做**：用户继续月光（作为反例）。

**候选节点**：N1 解析引擎 / N2 摸底 / N3 预算逻辑 / N4 保险教学 / N5 自检对比 / N6 兴趣分析 / N7 交互形态 / N8 储蓄状态识别+存量配置（新增）。

**五层下钻要点**：
- **N1 解析引擎**：L1 纯规则/规则+澄清/全人工/粗分；保留"规则+澄清"，剪掉全人工与粗分；**新选项**＝手抄降级模式。
- **N3 预算逻辑**：保留"先储蓄后消费+阶梯储蓄率"，剪掉零基（繁琐）与固定 50/30/20 为主用；**新选项**＝预算分类用上月消费做基线、只砍可优化项。
- **N7 交互形态**：对话+上传账单为主干，手抄兜底。
- **N8（新事实引入）**：储蓄状态识别→两条路线；存量用标准普尔象限。

**重钻记录**：
- 新事实 1（开源、无个人信息）→ 剪掉个人财务问卷，改产品定位。
- 新事实 2（阶梯储蓄、3 个月一阶）→ 剪掉"一步到位储蓄率"，新增阶梯分支。
- 新事实 3（有储蓄但不会分配）→ 新增 N8 存量配置，引入标准普尔象限。
- 新事实 4（三阶段收入分层分配 + 两条铁律）→ **剪掉**旧分支"按月份阶梯储蓄 5→10→15→20%"；**新增**分支"按税后收入分阶段定 刚需/欲望/储蓄 比例（阶段1: 70/20/10、阶段2: 50/30/20、阶段3: 40/30/30）"；固化两条铁律：①保障类保险→刚需、理财型保险→储蓄，理财保险不占刚需；②先划走储蓄、再花剩余（先储蓄后消费）。
- 新事实 5（决策引擎式摸底 + 多收入来源）→ 摸底从"问支付方式"升级为**三轮穷尽收集**（收入与背景 / 全部固定开支 / 确认与调整），产出「个人收支画像表」；收入口径改为**总收入（多来源：工资+家人支持+副业等，税后）**，区分稳定/不稳定；第六节新增"比例调整确认"（对比当前刚需占比 vs 目标比例，决定是否调整及用折中方案）。
- 新事实 6（月度收入波动）→ 月度复检从"每周 track + 每月滚预算"升级为**每月整理时先重新确认收入是否有增减**（工资/家人支持/副业/投资收益），收入变动则更新画像表、重新判定阶段、调整预算与储蓄比例。
- 新事实 7（逐条审视整改 8 项）→ ①**必改**：转账不再一刀切"非消费"，单挑出来逐笔问性质（刚需 vs 非消费），防房租/赡养被误判；②三阶段增量=两路线共用（B 额外做存量）；③阶段判定两步法（收入分档定基准 + 刚需占比微调）；④"储蓄只升不降"澄清为**比例口径**；⑤被问产品时标准话术；⑥账单收入与摸底收入对账；⑦阶段1 极端预案（刚需>80% 时储蓄 5% 起步或暂不设）；⑧隐私操作提示（文件阅后即删）。
- 新事实 8（虚构演示验证 + 刚需锁定规则）→ 用虚构用户跑通 8 步流程，验证发现刚需占比 55%–80% 的中等偏高档折中覆盖不了 → 新增「刚需锁定规则」：刚需篮子按实际金额锁定，剩余先划储蓄（向阶段目标渐进逼近）再分欲望；与两条铁律一致。
- 新事实 9（刚需占比优化评估 · 双通道）→ 新增「刚需占比优化评估」：①支出端问卷（房租谈价/在家做饭/交通改地铁/套餐/债务降息/取消订阅，逐项估算可省额）；②收入端问卷（空余时间兼职意愿：外卖/家教/技能变现，估算可增收额）；综合后按用户意愿采纳，优化后的刚需/收入代入重判阶段或微调预算。
- 新事实 10（收入端补 · 公司内增收）→ B 收入端问卷扩充为三层：①公司内增收（晋升/加薪/内部创业/内部转岗/项目奖金/加班补贴）；②公司外兼职（外卖/跑腿/家教/线上）；③技能变现（设计/写作/翻译/辅导）；合计估算可增额，量力而行不强求。
- 新事实 11（README 开源化）→ 新增 `LICENSE`（MIT 标准文本，Copyright (c) 2026 budget-by-income contributors，不出现个人名）；README「开源说明」升级为「开源许可（MIT）」+ **发布前自查清单**（个人信息扫描 / 样例虚构 / 原始素材不打包 / 许可证齐全 / 免责可见 / 平台合规）；目录结构补 LICENSE 与 demo/。
- 新事实 12（第三次审视 · 同步遗漏修复）→ 审视 SKILL.md/README/LICENSE 三文件：发现转账规则升级后 **§五第3步 与 README 功能清单残留旧表述"转账（非消费）"**（与 §四"不硬判"矛盾）→ 两处同步修复；README 功能清单补齐「刚需占比优化评估」「收入随月更新」「多来源收入口径」；LICENSE 无问题（健康）。
- 新事实 13（优化评估触发顺序固化）→ 用户点出"收入/刚需是否做了优化"的疑问 → 发现**演示1（小李）漏跑优化评估**（根因：第五节流程未把「刚需占比优化评估」挂在强制触发点）→ 修复：第五节第6步新增**先决检查**（刚需占比 ≥ 阶段目标或储蓄不达标 → 必先跑优化评估再生成预算）；演示1 补跑优化评估（支出端省 500：外卖改自做/打车改地铁/取消订阅；收入端晋升 `[需验证]`），储蓄直接达 20% 目标，自检对比与验证结论同步更新。
- 新事实 14（README 补输入输出完整流程）→ README 新增「输入与输出（完整流程）」节：首月输入清单（账单文件/摸底问答/现金）+ 输出清单（画像表/开销分析/路线阶段/优化结论/预算/存量配置/保险预算/自检对比）+ 每月循环（输入=收入确认+账单，输出=滚动预算/进度/建议）；附隐私提示（只收数字、文件阅后即删）。
- 新事实 15（安装测试 + 微信信息区补全）→ 安装到 .user_skills 后跑 13 项冒烟测试（发现机制/两平台样例解析/核心规则数字闭合）全部 PASS；测试暴露微信 xlsx 也有**信息区**（标题/昵称/时间/共N笔，约 15 行后才到明细表头）而 SKILL.md 未说明 → 补齐微信部分信息区说明（与支付宝部分对称）；重新打包 zip 并重装保持发布版与安装版一致。

## Phase C 苦集灭道剪枝记录

| 岔路 | 苦 | 根因节点 | 止息分支 | 判定 |
|---|---|---|---|---|
| 纯规则解析 | 陌生商户误判 | N1 触发阈值 | 并入对话澄清 | 保留并入 |
| 全人工解析 | 繁琐流失 | N1 交互 | 手抄降级 | 剪掉 |
| 粗分不细分 | 转账当消费、预算失真 | N1 收支判定 | 细化消费/转账/中性 | 剪掉 |
| 零基预算 | 逐笔分配繁琐 | N3 规则 | 先储蓄后消费 | 剪掉 |
| 纯对话无账单 | 数字靠回忆不准 | N7 输入 | 上传账单为主 | 剪为辅助 |
| 一步到位储蓄 | 砍太狠、伤快乐、反弹 | N3 储蓄率 | 阶梯式 3 个月一阶 | 剪掉 |
| 只给保险预算 | 用户拿到数字不会配 | N4 教学 | 加比例+优先级+提醒持牌 | 保留升级 |

**道（可执行流程）**：见 SKILL.md 第五节（8 步月循环），两条路线（零基础→三阶段收入分层分配；有储蓄→标准普尔配置）。

## 剩余本质苦 & 预案

- **用户粘性**（导出一次就不坚持）→ 每周轻量 track + 自检对比给出"一年后"激励；作者负责拉新。
- **账单格式版本变动** → 解析层"收/支列权威 + 对话澄清 + 手抄降级"兜底，字段变动不崩。
- **合规** → 死守不荐产品/不给法律意见/提醒持牌；README 与 SKILL.md 双处免责声明。
- **止损 checkpoint**：首版先跑通微信 xlsx 单链路，验证后再加支付宝；解析正确率不足则退回手抄模式。
